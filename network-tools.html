Which network tool should you use?

Start with the symptom, not the tool name. If a domain points to the wrong server or mail stops after a DNS change, use DNS Lookup. If you need the public address visible to internet services, use Public IP Checker. If you are planning an IPv4 subnet, use the CIDR Calculator. If HTTPS shows a certificate warning, inspect the certificate with the SSL Certificate Checker. If you only need to know whether this browser can attempt to reach a URL, use the Reachability Checker.

A simple troubleshooting sequence

For a website that suddenly stops working, a useful order is: confirm the hostname with DNS Lookup, inspect the TLS certificate if HTTPS is involved, then test reachability from the current browser. These checks answer different questions. A valid DNS answer does not prove the web server is healthy, and a valid certificate does not prove the application behind it is working.

For local network planning, the CIDR calculator is different from the live lookup tools: it performs deterministic subnet math in the browser and does not need to contact a remote infrastructure service. Public-IP, DNS and certificate checks depend on current external responses, so their results can change over time.

Why these tools are separated

A browser can calculate CIDR locally, but it cannot directly inspect the TLS certificate bytes of an arbitrary remote site. NexusNova therefore uses the narrowest appropriate method for each task and identifies third-party public APIs where one is needed.

Network-tool privacy and limitations

Public-IP and certificate lookups run only when you request them. Third-party services involved in a lookup receive the network request as they would for any direct web call. High-stakes security decisions should still be verified with your hosting provider, certificate authority or local command-line tooling.

None of these tools is presented as a penetration test, malware scanner, global uptime monitor or substitute for server logs. Their job is to answer one narrow network question at a time and make the limits of that answer visible.

Different network checks answer different questions

DNS lookup shows public records returned by a resolver, CIDR calculation describes an address range, certificate checking reads TLS certificate metadata, and reachability testing asks whether the current environment can test a destination. These signals are related but not interchangeable.

Public network information can change without a change to your device. DNS caching affects when new records appear, certificates have validity windows, and firewall or routing rules can make a mathematically valid address unreachable.

Do not over-interpret a clean result

A correct DNS record does not prove application health, and a valid certificate does not prove an application is secure. Use the result as one diagnostic signal alongside the configuration you actually control.
