How it works

One human. One action. One verifiable approval.

The user experience stays simple while the verification layer keeps the action context attached to the approval flow.

01 • PRESENT

Verify a live human

The camera flow asks for a short natural response and checks live facial motion before the approval can continue.

02 • BIND

Bind the exact action

The approval is associated with a specific operation — for example a deploy, refund, export, account recovery, or high-value transaction.

03 • RECEIPT

Create a verification receipt

The final product can return a tamper-resistant receipt containing the action reference, verification result, timing, and proof metadata.

Security & privacy

Keep the complexity behind the interface.

The prototype uses on-device face landmark analysis for the live camera interaction. A hardened production system would add stronger replay resistance, device/passkey proof, nonce handling, action hashes, signed receipts, abuse controls, and independent security review.

Minimal camera exposure

The interface is designed around short verification moments rather than long recording sessions.

Replay-aware architecture

Randomized challenges, timing checks, nonce binding, and device signals form part of the planned anti-replay baseline.

Action-specific proof

The goal is not only “a human was present,” but “a human approved this exact action.”

No identity claim by default

HumanProof is positioned around presence and conscious approval, not automatic real-world identity claims.

FAQ

HumanProof, explained simply.

Is HumanProof face recognition?

No. The core product concept is to prove that a live human consciously approved a specific action. It does not need to identify that person by name.

Does the prototype equal production-grade liveness?

No. The current camera experience is a working prototype. Production hardening would require stronger anti-replay and anti-injection controls, backend verification logic, monitoring, and external security review.

Can businesses integrate it without a full app?

Yes. The intended commercial entry points are verification links, an embedded web SDK/widget, and a REST API.

Is production verification free?

No. The commercial direction is free interface evaluation or sandbox use, with paid production verification.
