How this category is organized

Use resizing when pixel dimensions need to change, compression when file size is the main problem, format conversion when compatibility matters, OCR when readable text must be extracted, and metadata cleanup when you want a fresh copy without common embedded EXIF or GPS details. The CCTV and paper-size tools solve narrower tasks and state their own limits on the relevant page.

Trust and privacy

Image processing can affect transparency, text edges, colour, detail and metadata, so keep the original before making a delivery copy. Browser-focused tools reduce unnecessary file movement where supported, but each tool can have different library or format requirements. Check the page-specific notes, inspect the exported image at normal zoom, and avoid treating enhancement or OCR output as recovered information that was never present in the source.

Pick an image tool by deciding whether you need pixels, format or file size changed

Resizing changes pixel dimensions, compression targets file size and encoding efficiency, and format conversion changes how image data is stored. These operations can be combined, but doing the minimum necessary usually makes quality easier to preserve.

Worked example / practical use: A 4000-pixel photo intended for a small web card may first need sensible dimensions and then compression. A transparent logo that only needs broader compatibility may need a format decision instead, because converting to JPG would remove transparency.

Always keep the highest-quality original before creating delivery copies. Check transparency, text edges, faces, gradients and metadata according to the task. There is no single “best” image format for every use: photographs, screenshots, logos and print files have different requirements.

Before you rely on the result

  • Decide whether the real goal is dimensions, format, privacy or file size.
  • Keep the original before processing.
  • Inspect the output in the environment where it will be used.
